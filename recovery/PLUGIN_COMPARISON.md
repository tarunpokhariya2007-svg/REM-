# Recovered Plugin Comparison

This comparison is based on the recovered source preserved under `recovery/original_plugins/`, the current reconstructed files in `plugins/`, `actions/`, and `core/`, loader behavior, README, and declared requirements. Sources were parsed/read, not run. “Original” below means the recovered historical copy and does not imply it is the correct implementation to restore.

## Matching plugin comparison

## Dependency and configuration compatibility

- Current optional dependencies are declared in `requirements.txt`; no installation was performed. The current configuration path is `memory.config_manager` and plugin `PLUGIN_SETTINGS`, with credentials kept outside source.
- Recovered `calorie_counter` imports OpenCV and NumPy; both are in the current requirements. Recovered `chat_takeover` expects Pillow, `mss`, NumPy, `pyautogui`, `pyperclip`, and `pygetwindow`; dependencies are declared except the complete model/provider runtime behavior needs testing. Recovered `_telegram_ops.py` uses Pillow, `mss`, and deferred audio/video/model paths; the `av` module is not declared in `requirements.txt`, so its audio path would need graceful failure or a separately approved dependency. Recovered game automation depends on Windows/process/UI Automation facilities already declared, but exact runtime behavior must be tested before use.
- Current Gmail/Calendar integrations use the reconstructed `_google_oauth.py` and Google API/OAuth dependencies. No historical helper was available for behavioral comparison.
- The recovered Telegram pair is mostly lazy about external/service work, but its broad feature set uses HTTP, screenshot/camera capture, optional speech/transcription paths, persistent worker state, and Telegram credentials. Confirm every dependency and data-egress gate before adaptation.
- The Hostinger archive README documents an older VPS pairing/deployment flow and JARVIS naming. Never follow its deployment instructions as part of this local plugin audit; they are historical documentation, not authorization to access a server.

## Summary

Recovered code contains substantial features absent from reconstruction, especially ADS-B aircraft monitoring, structured contract review, autonomous chat takeover, rich Telegram operations, goal-based hydration, and focus/list conveniences. Aircraft tracking and the shopping-list check-off/multi-item subset were adapted; other current implementations remain active. Reconstruction contains current REM adapters and stricter architecture fit, especially tool routing, file-copy safety, current provider/config integration, confirmation gates, and a restricted Telegram command surface. No historical plugin should replace its current counterpart until the specific API, safety, and regression checks in `INTEGRATION_PLAN.md` are completed.
