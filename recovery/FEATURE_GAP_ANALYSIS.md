# REM Original Plugin Feature-Gap Analysis

Audit scope: recovered files under `recovery/original_plugins/loose/` and the preserved Hostinger archive, current `plugins/`, `actions/`, `core/`, the current loader, README, and requirements. Recovered originals were preserved unchanged. Static import/call inspection and mocked tests were used; no recovered plugin was run against a real account/service.

## Active security review notes

The current project already contains useful controls, but static inspection is not a security certification and no external service was exercised:

- `plugins/chat_takeover.py` avoids the recovered auto-reply worker; current message sending delegates to the core confirmation path.
- `plugins/gmail_control.py`, `calendar_control.py`, `upload_video.py`, `obsidian_vault.py`, and `whatsapp_call.py` call `core.confirm` before consequential writes/sends. The confirmation card includes operation/target and details, but `core.confirm.resolve()` currently logs the completion result; it does not feed it into the live Gemini conversation. This can leave the assistant without a final spoken receipt. Not changed in this recovery pass because it is shared confirmation infrastructure and requires a focused lifecycle design.
- `plugins/telegram_remote.py` checks paired chat IDs and uses `on_external_text_command`, avoiding the prior trusted local-input route. Real Telegram sender identity, replay, rate-limit, emergency-stop and disconnect behavior were not externally tested.
- `plugins/home_assistant.py` restricts control to `light` and `switch` and requires confirmation. URL host/redirect policy is not independently hardened here; use only an explicitly trusted configured Home Assistant instance.
- `plugins/image_generator.py` sends the configured key to its configured endpoint using the HTTP client default redirect behavior. Endpoint trust/redirect hardening is a follow-up security fix; do not configure an untrusted endpoint.
- `actions/dev_agent.py` previously installed model-proposed dependency lists and missing imports without a separate approval. This recovery pass disables those automatic `pip install` paths; project output now reports the missing package and asks the user to approve a separate install. No package installation was run.
- OAuth token paths are configured by the user; helper uses explicit OAuth scopes but does not enforce path ACLs. Do not place tokens in the repository.
- `plugins/obsidian_vault.py` confines note paths to the configured root and confirms updates; recursive search reads matching Markdown files under that root.
- `plugins/excel_writer.py` writes exclusively to a new path and restricts formula syntax. `actions/code_helper.py` runs requested project code with a timeout but is not an OS sandbox; do not use it on untrusted code without review.
- Current screen and browser paths are preserved. Screen text and webpage/document content require untrusted-data treatment; a real browser CDP/Playwright interaction or real screen-control run was not performed in this pass.

These findings are recorded rather than silently implied fixed. They do not widen the newly integrated aircraft or shopping-list capabilities.
